# 第六版动画与操作测试报告

日期：2026-09-24。Apple Silicon Mac、Python 3.12.9、pygame-ce 2.5.8。沿用第五版界面与搜索内核，本次调整动画、输入和显示提交。

## 改动

- 将方块材质从按位置动态生成改为按数字预缓存。移动过程中保持同一材质，避免首次生成的帧尖峰和跨格变色。
- 使用五次平滑曲线，起止速度和加速度连续。正常移动耗时 165–205 ms，快速自动模式 115–145 ms。
- 移动完成即释放输入锁；合并回弹和新方块淡入独立播放。连续操作最多缓存 4 个方向，按输入顺序执行。
- AI 在移动时预计算下一步，计算结果等待动画完成和节奏间隔后执行。暂停或手动接管使旧结果失效。
- 启用垂直同步，去掉同步开启时的第二个帧率定时器；无同步时按屏幕刷新率进行高精度节拍控制。重复使用显示缩放缓冲区。

## 自动验证

15 项规则、搜索和 UI 集成测试全部通过，耗时 8.680 秒。UI 新增验证了：到达后立即接受下一步、快速输入的 4 步顺序、动画帧无新材质生成、动画未结束时 AI 已在计算、暂停丢弃提前算出的动作。原有存档、撤销、随机状态、输入与缩放映射、设置、主题和游戏结束验证通过。

## 绘制性能对比

SDL dummy，2160 × 1640 内部画布，20 次三格移动、每次 42 帧，共 840 帧。基线定期清空材质缓存，模拟首次进入新位置；新版预加载数字材质，不需按位置重建。新版计入 update 和 draw，旧版只计 draw。这是 CPU 绘制测试，不是屏幕 FPS。

| 指标 | 第五版 | 第六版 |
|---|---:|---:|
| 平均每帧 | 4.47 ms | 4.28 ms |
| 95% 分位 | 5.62 ms | 5.48 ms |
| 最慢一帧 | 23.94 ms | 11.79 ms |
| 超过 16.67 ms 的帧 | 20 / 840 | 0 / 840 |
| 三格移动的输入锁定 | 320 ms | 205 ms |

新版 840 帧内材质生成次数为 0。基线中触发新材质的 34 帧平均耗时 16.04 ms。原始数据：`validation/v6/before.json`、`after.json`。

## 实际显示窗口

Cocoa 驱动，1080 × 820 窗口，系统报告 60 Hz，`pygame.display.is_vsync()` 返回 true。每次运行 9 秒，排除前 1 秒预热。

| 场景 | 连续手动移动 | AI 自动玩 |
|---|---:|---:|
| 采样帧数 | 480 | 480 |
| 平均呈现间隔 | 16.67 ms | 16.67 ms |
| 95% 分位呈现间隔 | 17.72 ms | 17.03 ms |
| 最大呈现间隔 | 21.70 ms | 19.33 ms |
| 超过 1.5 个刷新周期的间隔 | 0 | 0 |
| 绘制与更新平均耗时，不含等待显示 | 5.58 ms | 4.74 ms |
| 绘制与更新最大耗时，不含等待显示 | 8.73 ms | 8.45 ms |

AI 使用标准 100 ms 搜索预算和正常速度，实际平均相邻两步 261.72 ms，最大 266.88 ms。原始数据：`validation/v6/native.json`、`native-auto.json`。

一次早期无细分计时的实机采样出现约 1 秒停顿；后续加入显示提交与计算分段计时的手动、自动复测均未复现，不能确定该次停顿的来源。保留早期日志 `native-previous-*.json`。这些是当前机器的短时测量，不保证所有系统负载下完全不掉帧；120 Hz 屏幕尚未实测。

动画预览由同一个 Python 渲染器按固定 60 FPS 输出为 WebP，用于查看运动曲线和输入衔接，不作为帧率测试数据。实际手感应以游戏窗口为准。

搜索核心未修改，第二版三局实测日志仍在 `validation/v2/`。更新保留真实存档、运行环境和导出图片，旧代码备份至 `backups/v5-source/`。
