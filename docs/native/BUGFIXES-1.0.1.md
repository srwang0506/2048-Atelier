# 原生版 1.0.1 修复记录

本轮先添加可复现的回归测试，再修复实现。修复前的 8 项针对性测试共出现 22 个失败断言；修复后全部通过。原有功能与经典模式优先顺序保持。

## 已修复

| 问题 | 修复 |
| --- | --- |
| 快速连滑后打开模式菜单或重新开始确认，棋盘仍会执行剩余滑动 | 弹窗、菜单统一暂停输入，取消未执行动作，将已提交动画归位 |
| 连续操作不断取消延迟写入，进度长时间未落盘 | 合并期间的新状态，但不推迟已排定的写入；切后台立即请求保存 |
| 主存档缺失时直接开新局，即使备用存档仍然有效 | 主文件丢失与损坏都尝试读取备用文件 |
| 提示“损坏原文件已保留”，下一次保存却覆盖了原文件 | 覆盖前将无法解码的原文件另存为 `progress-unreadable-UUID.json` |
| 经典存档能夹带远征状态，改变落子概率；历史帧也能带入错误模式状态 | 校验当前模式的专属字段与全部撤销 / 重做帧，拦截混合状态 |
| 每日存档能接受 2 月 30 日、99 月等无效日期 | 按公历月份天数和闰年验证日期 |
| 残局目标可与归档不一致，原路线可能为空或被篡改 | 校验目标、步数和标准步数；逐步重放原路线及解法，确认真实落子和终局 |
| 冲刺最后一步仍按棋盘形状、后续机会评分 | 搜索不超出剩余步数；最后一步按即时得分比较，最后两步对照完整概率枚举验证 |
| 复盘从长路线切到短路线时，旧游标可能越界 | 路线和游标一起切换；棋盘、方向文字和按钮共用受限索引，空路线也安全 |
| 提示弹窗、后台状态没有统一拦截撤销、AI 和能力入口 | 所有对局入口共用活动状态检查，恢复前不接受操作 |
| 键盘响应器在菜单中仍可能占用方向键，返回棋盘后焦点可能丢失 | 随对局是否可操作调整响应器，菜单期间释放键盘焦点，返回后重新获取 |
| 关卡合并动画尚未结束就选能力，旧动画或旧滑动可能影响下一关 | 选择能力前结束当前动画、清空待执行输入并暂停 AI |

iOS 后台保存还增加了有限后台执行时间的申请与释放。此 UIKit 分支和硬件键盘焦点调整尚未经过 iOS SDK 编译或真机验证，不能将主机测试视为设备验证。

## 实际验证

- **38 项核心 / 交互测试通过**：原有 25 项，加本轮 13 项回归。

- 冲刺最后一步：16 个棋盘检查即时得分选择；最后两步：8 个棋盘与完整随机落子概率枚举比较。
- 四种 SwiftUI 静态布局再次生成，通过现有图像内容检查。
- 更新搜索步数限制后，远征 AI 再次通过六关：138 次动作、6,422 分。
- Xcode 工程引用、图标、设备配置和 plist 检查通过。

测试输出见 `QA/logs/bugfix-tests.log`、`QA/logs/bugfix-expedition.log`，首次复现摘要见 `QA/logs/bugfix-before-summary.log`。
